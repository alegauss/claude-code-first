# F202 A gate run in a checkout that something else is writing reports on the moving tree, not on the change

| Field | Value |
|---|---|
| Status | active |
| Topic | Commits and concurrent sessions |
| Grade | R3/S3 |
| Cases | roadkeep, Shio |
| Contrary | none |
| Harness facts | none |

## Claim

A test or gate run reads the live working tree, so another session's uncommitted edits, a
second run of the same gate, or other work writing to the repository during the run produced
reds and counts that were not about the change, measured in both roadkeep and Shio, and each
project answered with a mechanism that makes the run say so.

## Mechanism

A gate has no notion of whose edits it is reading. When several sessions share one checkout,
one session's run sees the other's half-finished files; two runs of one gate share its log and
build directory and corrupt both; a file written mid-run makes a value read at collection
disagree with the disk. The output looks like any other red or green, so the session either
chases a defect that is not there or, if it knows the tree is shared, has to argue in its
commit message that the red is someone else's. The remedies found make the run detect the
condition: a lock per gate, a snapshot taken at collection, a fingerprint that names the file
that moved.

## Independence

Two independent origins. roadkeep's and Shio's failures are each in their own suite and
their own gate runner (pytest fixtures in roadkeep, `run-gate.mjs` in Shio), and neither
remedy was copied from the other: the lock, the snapshot and the fingerprint are three
different mechanisms. Within each project the failure recurred on separate occasions
(roadkeep 2026-08-04, 2026-08-05 and 2026-08-17; Shio 2026-08-17 and 2026-09-14).

## Counter-evidence

None found at the pins. Two limits: Shio's overlapping runs came from one session's background
job, not from two sessions, and roadkeep's RK263 names worktree operations beside the suite
without saying which session ran them, so the sources support "something else writing the
checkout", not always "another agent session". The other three cases record no such incident,
which is not evidence that it did not occur there.

## Grade

**R3**: independent failures in two projects. **S3**: both projects counted the effect in
their own sources, Shio's collision at 3 errors over 1092 tests against 1894 green, and
roadkeep's run at six failures, five not about the code, against 1940 passed. Not S4: the
lock and the fixture are mechanisms that detect the condition, and the pins record no occasion
on which either was seen to refuse or skip a run.
