# F201 Agent sessions sharing one checkout commit each other's work unless each commit stages only its own paths

| Field | Value |
|---|---|
| Status | active |
| Topic | Commits and concurrent sessions |
| Grade | R2/S2 |
| Cases | roadkeep, Shio |
| Contrary | none |
| Harness facts | none |

## Claim

When two or more agent sessions work in one checkout at once, a commit that stages more than
its own task's paths carries the other session's uncommitted work under its own message; this
happened three times in roadkeep, twice after a remedy for it had shipped, and Shio's sessions
avoided it by staging by path, against their own written rule to use the stage-everything tool.

## Mechanism

Sessions in one working tree share one index and one set of files. Whatever stages the whole
tree, or a whole file, takes the other session's edits with it: the commit tool, a hook that
stages a file to write a version into it, or a command that prints a stage line naming a file
both sessions touched. Nothing fails: both commits are green, so the misattribution is found
only when someone reads a diff. Staging a declared list of paths is the one step that
separates the two sessions' work, and it fails where both sessions edit the same file.

## Independence

roadkeep's three incidents are one project's failures (rule 1), separated in time and by an
attempted fix, so they establish recurrence within roadkeep. Shio records the same condition,
several sessions in one tree with a stage-all commit step, in its own commit messages, but it
records the hazard avoided, not the failure; it corroborates the mechanism without adding a
second origin of the failure. Whether Shio's staging by path was learned from roadkeep is not
stated in either source, so it is not counted as an independent remedy either. The claim and
path mechanism in roadkeep is a remedy of the tool, invented there (rule 2).

## Counter-evidence

None found at the pins. Two limits: roadkeep's rationale for RK280 notes that staging by path
does not separate two sessions editing the same file, which is what the RK1117 incident then
showed, so staging by path is not a full remedy. And an incident nobody filed leaves no trace,
so whether the remedies ended the incidents in roadkeep is not known.

## Grade

**R2**: three separate incidents in roadkeep, two of them after the first remedy; Shio adds
corroboration of the condition, not a second origin. **S2**: each incident is recorded by a
ledger entry, a rationale section and a commit. roadkeep's RK280 rationale gives the line
counts of the misplaced hunks, which describe the incident rather than measure how often it
happens, so the grade stays at S2. Shio's count of 11 commits is repeatable at the pin with the
command given, but it counts commits that avoided the effect by staging by path, not commits
that carried another session's work, so under ../grading.md it does not measure the finding.
